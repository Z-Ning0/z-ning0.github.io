游戏挂到子目录后，为什么场景图 404？

学习短记

游戏部署到网站的子目录后，页面能打开，场景背景图却返回 404。下面用一张自制 SVG 复现：同一张图，一次用 <img> 加载，一次用 CSS 背景加载。

页面地址是 /play/demo/，样式表在 /play/demo/assets/site.css。HTML 和 CSS 变量拿到的都是 ./images/scene.svg：

<img src="./images/scene.svg" alt="">
<div class="scene"></div>

/* assets/site.css */
.scene { background-image: var(--scene); }

document.querySelector('.scene').style.setProperty(
  '--scene', 'url("./images/scene.svg")'
);
同一个相对路径，哪条请求会 404？

Chrome 实际请求：

200  /play/demo/images/scene.svg
404  /play/demo/assets/images/scene.svg

<img src> 相对页面地址解析。背景图的 url() 则是在样式表通过 var(--scene) 使用时解析，因此相对的是 assets/site.css 所在目录。即使用 JS 把变量写到了元素上，也不改变这个例子里背景图的解析位置。

修复：先把地址算出来，再交给 CSS

const path = './images/scene.svg';
const url = new URL(path, document.baseURI).href;
document.querySelector('.scene').style.setProperty(
  '--scene', `url("${url}")`
);

改完后，Chrome 不再请求 assets/images/scene.svg；背景图和 <img> 都指向返回 200 的 /play/demo/images/scene.svg。查同类问题时，先看 Network 里实际请求的完整地址，不要只比较代码里的路径字符串。

参考：W3C CSS Custom Properties 规范
