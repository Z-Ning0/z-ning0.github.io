通知为什么跳回了错误的 Cursor 窗口？

学习短记

同时开着两个项目。Claude Code 会话从 repo-a 启动，中途执行 cd 去看 repo-b。任务结束后，通知应该带你回 repo-a，却打开了 repo-b。

第一次修复：不直接用当前目录

最初，通知把事件里的 cwd（当前工作目录）拼进 Cursor 的跳转链接。Agent 如果从 repo-a 进了 repo-a/src，链接也跟着变成了子目录，Cursor 可能会把它当成另一个工作区打开。

第一次修复用 git rev-parse --show-toplevel 把当前目录归一成仓库根。这样，repo-a/src 和 repo-a 就会跳到同一个地方。

如果 Agent 从 repo-a 切到了 repo-b/src，Git 会给出哪个仓库根？

repo-b。Git 找的是传给它的目录所在的仓库，并不知道会话从哪儿启动。第一次修复解决了同仓库内进子目录，没有解决跨仓库切换。

第二次修复：先找会话是从哪儿启动的

从会话记录（transcript）的前 10 行找第一条带 cwd 的记录，再把那个路径交给 Git。找不到记录时，仍回退到通知事件里的当前目录。

  • 只进子目录： repo-a/src → 查当前目录得到 repo-a，查会话起点也得到 repo-a。
  • 切到另一个仓库： repo-b/src → 查当前目录得到 repo-b（跳错），查会话起点才得到 repo-a。

cwd 回答的是「Agent 现在在哪」，通知需要的是「这段会话属于哪个工作区」。 Git 能把路径归一到仓库根，但前提是先给它正确的路径。
